# 食光 · 私人食谱

## 代码与数据分类

先看[代码分类与修改范围](docs/代码分类与修改范围.md)：列出维护者可修改的公共内容、各使用者的本机自定义数据，以及功能代码的编辑位置。

| 内容 | 维护位置 | 影响 |
| --- | --- | --- |
| 公共好物及图片 | `content/recommendations.json`、`recommendations/` | 发布后更新公共列表；已导入的个人食品保持原样 |
| 公开参考食谱 | `content/recipes.json` | 发布后更新公共模板；已存私人副本保持原样 |
| 初始食材及默认计算 | 本机源码 `lib/foods.json`、`lib/nutrition.ts` | 需构建、迁移兼容检查后发布 |
| 个人食材、食谱及日期配餐 | 使用者浏览器本地存储 | 不在本仓库，维护者不能在这里直接查看或编辑 |
| 网站功能与界面 | 本机源码 `app/`、`components/`、`lib/` | 修改源码后构建发布，不手改 `assets/` 的压缩文件 |

当前专属码只区分本机档案，不是云端账号或密码；个人云备份尚未接入。源码中保留的旧 D1 / ChatGPT 登录接口不是当前静态网站的后台。

手机配餐工具，支持可编辑食材库、每天的餐次记录、营养汇总和历史查询。

所有运行文件均包含在此目录内，可部署到普通 HTTPS 静态网站根目录，配餐功能不需要后端或 ChatGPT 账号。好物推荐使用本站 content/recommendations.json 和 recommendations/ 图片目录，随 GitHub Pages 一起发布，不需要云数据库或管理登录。内容在打开、切回页面及每分钟联网检查时更新。可直接将推荐食品及每100克营养导入本机食材库；重复导入不会覆盖自己改过的值。

配餐数据保存在当前设备、当前浏览器的网站存储中，不会自动跨设备同步。本版按要求不展示导入导出入口；不同手机、浏览器或网址的数据独立，请勿清理网站存储。

蛋白折算为用户自定义估算规则：肉、蛋、奶 100%，蔬菜、水果 50%，其余 80%，支持逐项修改，不表示人体实际吸收率。

## GitHub Pages

将本目录的应用文件放在仓库根目录，在 Settings → Pages 选择 Deploy from a branch → main → /(root)。本版本需要部署在网站根路径；不要将它放在二级项目路径下。

## 留言

食谱夹底部的“留言与建议”进入仓库的 GitHub Issue 表单，提交需要登录 GitHub，内容公开。`.github/ISSUE_TEMPLATE/feedback.yml` 将留言自动指派给仓库维护者；通知通过维护者的 GitHub 通知设置送达。

## 更新兼容

保持现有域名与本机存储键；公共参考食谱更新不会自动改写使用者保存的食谱和日期配餐。发布新版本时保留旧版本带哈希的 JS/CSS 文件，避免影响已经打开的页面。
